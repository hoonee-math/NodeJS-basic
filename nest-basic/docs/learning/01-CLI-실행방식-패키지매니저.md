## 1. CLI 실행 방식

### 1.1 개념 차이 요약

CLI 실행 방식의 차이는 **`nest` 명령어를 어떻게 가져와서 실행하느냐**의 차이다.
프로젝트가 생성된 이후의 실행·빌드·런타임에는 **전혀 관여하지 않는다**.

즉,

- CLI는 개발 편의를 위한 도구
- Nest 애플리케이션 자체는 CLI 없이도 동작

---

### 1.2 방식 비교

| 구분       | npm 전역 설치              | npx 실행        |
| ---------- | -------------------------- | --------------- |
| 사용 명령  | npm install -g @nestjs/cli | npx @nestjs/cli |
| 설치 위치  | PC 전역                    | 임시 다운로드   |
| PC에 남음  | O                          | X               |
| 버전 충돌  | 발생 가능                  | 거의 없음       |
| 팀/CI 환경 | 불리                       | 유리            |
| 현재 권장  | X                          | O               |

---

### 1.3 자주 헷갈리는 질문

**Q. npx를 쓰면 nest 명령어를 안 쓰는 건가?**
A. 아니다. 내부적으로 동일하게 `nest` 명령어를 실행한다. 둘다 

**Q. 전역으로 설치한 nest를 지워도 기존 프로젝트에 문제 없나?**
A. 없다. CLI는 프로젝트 실행과 무관하다.

**Q. CLI는 언제 필요한가?**
A. 프로젝트 생성(new), 코드 생성(generate) 같은 개발 보조 작업에서만 필요하다.

## 2. 의존성 설치 방식

### 2.1 개념 차이 요약

의존성 설치 방식의 차이는 **라이브러리를 디스크에 어떻게 배치하고 Node가 어떻게 찾느냐**의 차이다.
이 선택에 따라 `node_modules`가 생길 수도 있고, 생기지 않을 수도 있다.

이 영역은 **CLI 실행 방식(npm -g, npx)과 완전히 별개**다.

---

### 2.2 방식 비교

| 패키지 매니저 / 방식 | node_modules | 특징                                   |
| -------------------- | ------------ | -------------------------------------- |
| npm                  | O            | 가장 보편적, 호환성 최고               |
| yarn (node-modules)  | O            | npm과 유사                             |
| pnpm                 | O            | 실제 파일은 .pnpm, 링크 구조           |
| yarn PnP             | X            | .pnp.cjs로 경로 관리, 호환성 이슈 잦음 |

---

### 2.3 자주 헷갈리는 질문

**Q. npx를 쓰면 node_modules가 안 생기나?**
A. 아니다. node_modules 생성 여부는 패키지 매니저 선택에 따라 결정된다.

**Q. pnpm은 node_modules가 없는 방식인가?**
A. 아니다. node_modules는 존재하지만 내부가 링크 구조다.

**Q. node_modules가 아예 없는 경우는 언제인가?**
A. Yarn의 PnP 방식을 선택했을 때뿐이다.

## 3. 프로젝트 실행 방식

### 3.1 개념 차이 요약

프로젝트 실행 방식은 **프로젝트를 어떻게 생성했는지(npm, npx)** 와 무관하다.
실행은 오직 **프로젝트 내부 설정(package.json, node_modules)** 만을 기준으로 동작한다.

즉,

* 생성 방식은 과거의 이력
* 실행 방식은 현재 프로젝트 상태

---

### 3.2 실행 명령어

| 구분                  | 의미                       |
| ------------------- | ------------------------ |
| `npm run start`     | package.json의 scripts 실행 |
| `npm run start:dev` | 내부 nest CLI + watch 모드   |
| 참조 대상               | node_modules/.bin        |
| 전역 CLI 영향           | 없음                       |
| npx 사용 여부           | 무관                       |

---

### 3.3 자주 헷갈리는 질문

**Q. npx로 만들었으면 npx로 실행해야 하나?**
A. 아니다. 실행은 항상 `npm run` 기준이다.

**Q. 전역 nest CLI를 지우면 실행이 안 되나?**
A. 아니다. 프로젝트 내부 CLI로 정상 실행된다.

**Q. npm과 npx 차이가 실행에도 영향을 주나?**
A. 아니다. 실행 단계에서는 완전히 분리된 개념이다.

---

## 최종 한 줄 요약

CLI 실행 방식은 **명령어를 어떻게 실행하느냐**의 문제이고,
의존성 설치 방식은 **라이브러리를 어떻게 설치하느냐**의 문제다.

두 개는 서로 영향을 주지 않는 완전히 다른 레이어다.
